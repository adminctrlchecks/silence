You are working on an existing production-style web application. The core implementation and functionality are already completed. DO NOT rebuild the application from scratch and DO NOT change existing business logic, APIs, database logic, authentication logic, workflow functionality, or working features unless absolutely required for the UI changes.

Your task is to perform a complete end-to-end UI/UX quality audit and then improve the frontend implementation systematically.

IMPORTANT:
Do not make random visual changes page-by-page. First inspect the entire frontend structure, routing, shared components, layouts, CSS/Tailwind configuration, design tokens, authentication screens, dashboards, forms, navigation, cards, tables, modals, and responsive breakpoints. Understand the existing design language before modifying anything.

3. AUTHENTICATION UX — IMPORTANT
================================

Redesign the authentication entry experience so that User and Admin sign-in are presented through ONE unified sign-in screen.

Do NOT keep a separate Admin Sign-in section at the bottom of the page.

At the top of the sign-in card, provide a clear two-option toggle:

[ User ] [ Admin ]

The initial/default selection should be User.

When User is selected:

* Show the normal user authentication fields.
* Keep the existing user authentication functionality unchanged.

When Admin is selected:

* Show Admin Username.
* Show Admin Password.
* Show the appropriate admin sign-in button/action.
* Preserve the existing admin authentication functionality.
* Do not expose unnecessary admin functionality in the user view.

The two modes must use:

* The same card
* Same container
* Same alignment
* Same spacing system
* Same typography
* Same button placement
* Same responsive behavior

Only the authentication content should change.

The transition between User and Admin should feel intentional and polished.

Use a segmented-control/toggle style rather than two unrelated buttons.

Example structure:

Sign In

[ User ] [ Admin ]

User selected:
Email / Username
Password
Forgot password?
[ Sign In ]

Admin selected:
Admin Username
Admin Password
[ Admin Sign In ]

Do not duplicate the entire authentication page.

Do not change backend authentication behavior unless required to connect the existing UI correctly.

4. DESKTOP RESPONSIVE DESIGN
============================

The application must look professionally aligned on desktop screens.

Check common viewport sizes such as:

* 1280px
* 1366px
* 1440px
* 1536px
* 1920px

Ensure:

* Content does not become excessively stretched.
* Main containers have sensible max-widths.
* Sidebar and main content align correctly.
* Cards do not have inconsistent widths.
* Tables do not break layouts.
* Forms remain readable.
* Navigation does not overlap.
* Buttons remain properly aligned.
* Long text does not unexpectedly destroy layouts.

Use responsive max-width containers instead of arbitrary fixed widths where appropriate.
