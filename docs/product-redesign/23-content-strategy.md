# Content Strategy

> Product language, terminology, content patterns, and message guidelines for Silence.

---

## 1. Current Content State

- User-facing copy is stored in `next-intl` message catalogs. `CURRENT`
- Admin UI copy is mostly hard-coded English. `CURRENT`
- Current homepage copy is too sparse to explain the product and includes technical user-facing language such as "JWT". `CURRENT`
- Status labels for user sessions are translated in user app/history. `CURRENT`
- Registration consent copy exists but does not yet link to Terms/Privacy. `CURRENT` gap
- There is no documented tone of voice, CTA convention, empty-state pattern, or legal disclaimer copy. `CURRENT`

## 2. Voice And Tone

| Quality | Direction |
|---|---|
| Clear | Explain what happens and why without jargon. `PROPOSED` |
| Calm | Avoid urgency/scare tactics around astrology or remedies. `PROPOSED` |
| Respectful | Users may share sensitive personal details; copy should be permission-based. `PROPOSED` |
| Practical | Remedies should be actionable and repeatable. `PROPOSED` |
| Honest | Distinguish computed chart data, admin content, and AI-generated interpretation. `PROPOSED` |

## 3. Terminology

| Concept | Preferred Label | Avoid |
|---|---|---|
| Product | Silence | Over-translating brand before decision. `NEEDS DECISION` |
| User | Reading user/seeker in docs; "you" in UI | "Consumer", "subject". `PROPOSED` |
| Admin | Admin/content operator | "Astrologer" unless role is confirmed. `ASSUMPTION` |
| Session | Reading | Raw `ReadingSession` or enum values. `CURRENT` `PROPOSED` |
| Questions | Guided questions/reflections | Survey, quiz. `PROPOSED` |
| Chart | Birth chart/astrology chart | Generic "chart" alone in onboarding. `PROPOSED` |
| Remedy | Personal remedy/practice | Treatment, cure, prescription unless legally approved. `PROPOSED` |
| AI | AI-assisted generation/translation | Magic, automatic truth. `PROPOSED` |

## 4. CTA Conventions

| Context | Primary CTA | Secondary |
|---|---|---|
| Homepage | Start your reading | See how it works, Sign in. `PROPOSED` |
| Registration | Continue / Create profile | Sign in. `PROPOSED` |
| Dashboard | State-specific next step | View history/profile. `CURRENT` `PROPOSED` |
| Questions | Save and continue | Back to dashboard. `CURRENT` `PROPOSED` |
| Chart | View your remedy | Edit birth details, Back to dashboard. `PROPOSED` |
| Remedy | Finish reading / View history | Back to chart. `PROPOSED` |
| Admin CRUD | Add/Create/Save | Cancel, Delete. `CURRENT` `PROPOSED` |

Use verbs that describe the outcome, not implementation: "Create profile" is better than "Submit"; "View your chart" is better than "Generate". `PROPOSED`

## 5. Error Messages

Pattern:
1. What happened.
2. Whether user data is safe.
3. What to do next.

Examples:
- "We could not save this layer. Your draft is still on this device. Try again." `PROPOSED`
- "We could not generate your chart right now. Check your birth details or try again." `PROPOSED`
- "Your session expired. Please sign in again to continue." `PROPOSED`

Do not expose raw API errors, stack traces, JWTs, or provider details. `PROPOSED`

## 6. Empty States

| Surface | Empty State |
|---|---|
| First dashboard | Explain the reading path and show Start reading. `PROPOSED` |
| No questions | Tell user content is being prepared; admin dashboard should surface the content gap. `CURRENT` `PROPOSED` |
| No history | "You haven't started a reading yet" plus CTA; current copy exists. `CURRENT` |
| No chart/remedy in history | Current detail page handles this; improve with section-specific explanation. `CURRENT` `PROPOSED` |
| Admin empty list | Explain how to create/import content and link to import where relevant. `PROPOSED` |

## 7. Success And Confirmation Messages

- Profile saved: concise inline/toast confirmation. `CURRENT` `PROPOSED`
- Password changed: clear sign-out/re-login explanation. `CURRENT`
- Question layer saved: confirm save and reveal guidance. `CURRENT` `PROPOSED`
- Reading complete: acknowledge completion and point to history/remedy. `PROPOSED`
- Admin delete confirmations: object name, consequence, irreversible nature. `PROPOSED`

## 8. Trust And Consent Copy

Required content themes:
- Why birth details are needed. `DOCUMENTED` `PROPOSED`
- What gets saved. `CURRENT` `PROPOSED`
- Links to Terms/Privacy before signup. `PROPOSED`
- AI assistance explanation at a high level. `CURRENT` `PROPOSED`

All final legal wording requires review. `NEEDS DECISION`

## 9. AI And Astrology Content

- Chart interpretation generated by Gemini should be presented as interpretation, not computed fact. `CURRENT` `PROPOSED`
- Remedy match details should be translated from technical rule reasons into user-friendly language. `CURRENT` gap `PROPOSED`
- Admin-facing AI answer rows should show source/review status clearly. `CURRENT` `PROPOSED`
- User-facing copy should not imply AI content is reviewed unless the specific content is reviewed. `PROPOSED`

## 10. Localization Copy Rules

- Keep strings short but not cryptic. `PROPOSED`
- Avoid idioms that translate poorly. `PROPOSED`
- Avoid uppercase for emphasis. `PROPOSED`
- Allow content-specific `dir="auto"` and native language names. `CURRENT` `PROPOSED`
- Use ICU plurals for counts. `PROPOSED`

## 11. Admin Content Rules

- Use operational labels: "Unreviewed AI answers", "Missing translations", "Import failures". `CURRENT` `PROPOSED`
- Table column names should be consistent across Questions/Answers/Remedies: Category, Level, Language, Status, Updated, Actions. `PROPOSED`
- Delete confirmations must use plain object names and avoid native browser dialog copy. `CURRENT` gap `PROPOSED`

## 12. Acceptance Criteria

- Homepage copy explains Silence without technical jargon. `PROPOSED`
- No raw enum/JWT/provider terms appear in user-facing surfaces unless intentionally educational. `CURRENT` gap `PROPOSED`
- Error/empty/success states use consistent patterns. `PROPOSED`
- Legal/trust copy is linked but not fabricated. `NEEDS DECISION`
- Translation-ready strings live in message catalogs where user-facing. `CURRENT` `PROPOSED`
